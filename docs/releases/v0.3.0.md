# v0.3.0

GitHub-only 开源发布。正式数据生命周期（DataPlan Confirmed → Data Ready）、
统一 JSON-only CLI 与 TEST-ONLY 离线 synthetic 示例已完成并通过跨平台验收。

## Highlights

- 完整生命周期：`SourceSelection` → `AcquisitionRequestPlan 1.2` →
  `DataAccessAuthorization`（single-use）→ Provider execution（FRED / local CSV）
  → 事务性 snapshot → `DataReadinessAssessment 1.1` → `DataReadyManifest 1.1`。
- 精确 session-evidence 绑定：完整 expected/observed sample & pre-sample
  session-set SHA-256 与显式 `ExplicitSessionScheduleSnapshot`。
- 统一 `data-lifecycle` CLI：JSON-only、稳定 exit codes、无自动确认/授权/
  选择/执行。
- TEST-ONLY synthetic 离线示例从显式输入一路到达 Data Ready。

## Lifecycle

```
hypothesis_draft → spec_review → data_plan → source_selection
→ acquisition_request → data_access_authorization → provider_execution
→ snapshot_verified → data_readiness → data_ready
```

每个状态都绑定上游 canonical hash；Ready ≠ Confirmed ≠ Authorized ≠ Executed。

## Trust boundaries

- 无自动 Provider selection、无自动确认、无自动授权、无 retry、无 fallback。
- Credential 仅非交互解析，绝不进入 artifact；CLI 不输出 secret 与 raw response。
- schedule snapshot 不接受任意 Python import path，不加载任意代码。
- Data Ready ≠ Analysis Authorized；schedule snapshot 确认不是数字签名。

## Breaking artifact schema changes

- `AcquisitionRequestPlan` 1.0/1.1 → 1.2（acquisition window、steps 绑定
  canonical hash、HTTP 参数净化）。
- `DataReadinessAssessment` 1.0 → 1.1；`DataReadyManifest` 1.0 → 1.1
  （完整 session evidence 绑定；`assessment_id`/`data_ready_id` 派生自完整
  canonical core）。
- 旧 artifacts 严格 fail closed，必须重新生成。

## CLI

- `market-validator data-lifecycle schema|validate <artifact-type> <path>`
- `source-selection generate|confirm|validate-confirmation`
- `acquisition generate|validate` · `authorization create|validate`
- `execution run` · `session-schedule validate|persist`
- `readiness assess|finalize|verify`
- exit codes：0 成功 / 2 无效输入或 blocked / 3 执行失败（授权已消费）/
  4 不可变输出冲突 / 1 内部错误。

## Known limitations

- 真实市场日历可能缺少 schedule evidence，真实油价/A 股示例可能保持
  unresolved/blocked（不伪造日历或日期）。
- 通用统计分析（analysis/robustness/report）尚未实现。
- 无自动 Provider selection、无 retry/fallback、无 paid access。
- 未发布 PyPI；`data fred fetch --live` 仅为 legacy provider diagnostic。
